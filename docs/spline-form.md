# Самостоятельная сплайн-форма

`Сплайн` находится в обычной палитре форм. У новой формы две точки: `(0, 0, 0)`
и `(0, 0, 2)` в блоках. Кривая служебная: видна в редакторах, в итоговый кадр
не рисуется. Отладка IK для неё не нужна. Миниатюра показывает саму кривую
и её точки в обычном ракурсе превью форм.

## Редактирование

Основная панель содержит точки, кнопки добавления/удаления, координаты и
замкнутость. Клик в списке или по точке в сцене выбирает точку;
Ctrl/Shift расширяют выбор. Гизмо перемещения и координаты меняют всю выбранную
группу. Delete удаляет выбранные точки. Ctrl+ЛКМ по кривой вставляет точку
в указанном месте, включая последний сегмент замкнутой кривой.

Копирование, вставка, распределение и перестановка находятся в контекстном меню
списка. У длинного списка собственная прокрутка. Для перемещения, поворота и
масштаба всей кривой используйте обычную панель трансформации формы.

В фильме и состояниях положения точек анимируются составным свойством
`curve`. В редакторе ключа доступны выбор и координаты, включая мультивыбор
и автоключ. Структура меняется в основной панели формы. ID точек сохраняются при
перестановке, вставке и Undo: ключи продолжают обращаться к тем же точкам.
Точка, добавленная после создания ключей, использует своё исходное положение,
пока оно не записано в ключ.

## Актёры и камера

У актёра фильма откройте обычную привязку Anchor. Выберите актёра со сплайном,
а для вложенного сплайна — соответствующую форму в списке креплений.
Можно воспользоваться штатной пипеткой. Когда целью выбран сплайн, появляются
прогресс и режим поворота. Прогресс анимируется в ключах Anchor; у каждого
потребителя он свой. Смещение остаётся обычной трансформацией привязки.
Работают наследование позиции/масштаба и «сохранить вид» при смене цели.

Чтобы несколько объектов двигались вместе, привяжите форму-якорь к сплайну,
а остальные объекты — к этому якорю обычным способом. Межактёрские ссылки
доступны в фильме; геометрия и анимация точек доступны и в редакторе состояний.

У камеры добавьте клип «Сплайн», выберите актёра и сплайн в его дереве форм.
Поля «Начало» и «Конец» стоят в одном ряду, названия видны при наведении.
Они задают проценты прохода за длительность клипа; кнопка
интерполяции задаёт изменение скорости. Например, 0 → 100 — полный проход,
100 → 0 — обратный, 40 → 40 — остановка. На замкнутом пути 0 → 200 даёт
два оборота. Поля меняют параметры клипа, не создают ключи. Отдельного графика
прогресса нет; несколько клипов позволяют собрать проход, остановку и возврат.
Выбор направления расположен в той же секции «Прогресс».
Смещение, углы и FOV — постоянные параметры этого клипа, маски каналов штатные.
Ручное перемещение камеры меняет смещение и углы через обратный расчёт кадра пути.
Tracker снова работает как обычный Tracker без специального сплайн-режима.

Для независимого взгляда на движущегося актёра добавьте выше по слоям обычный
Look либо Tracker с режимом наведения и включёнными только каналами углов.
Нижний клип «Сплайн» задаёт движение камеры. Можно вместо этого оставить
собственные углы или добавить угловое смещение к направлению пути.

## Другие применения

Через Anchor в фильме можно вручную расставлять формы блоков, моделей и другие
объекты вдоль одной кривой, задавая каждому собственный прогресс. При нулевых
смещениях 0/25/50/75/100% дают пять равномерных позиций на открытом пути;
у замкнутого 100% совпадает с 0%. Анимация прогресса даёт движение объектов,
анимация curve меняет сам общий маршрут. Привязка цели IK также использует
Anchor: цель руки или ноги может следовать по пути. Всё это относится к сцене
фильма; автоматического размножения форм, изгиба мешей и установки блоков мира
по сплайну пока нет.

## Математика и данные

- Используется прежний uniform Catmull–Rom Spline IK. Локальные точки формы
  не переписываются при трансформации всей формы.
- Процент пути измеряется по длине **после** полной мировой трансформации,
  включая вложенность, привязку источника и неравномерный масштаб. Таблица длины
  содержит 48 отрезков на сегмент — как у прежнего IK. Линейные ключи прогресса
  дают равномерное движение с точностью этой аппроксимации.
- Открытый путь ограничивает прогресс диапазоном 0–100%; замкнутый повторяет
  обороты, включая отрицательные проценты. Уменьшение прогресса движет назад,
  направление касательной по-прежнему соответствует увеличению прогресса.
- Режимы поворота: собственный, по касательной, горизонтальная касательная.
  Полный поворот использует параллельный перенос нормали от начала кривой,
  с распределённой компенсацией замкнутого шва. Вертикальная горизонтальная
  касательная использует предыдущее пригодное направление **вдоль кривой**,
  либо +Z; результат не зависит от предыдущего показанного кадра.
- +Z кадра направлен вперёд по пути. Перевод в углы камеры учитывается
  преобразованием yaw в TrackerFrame, без дополнительного разворота на 180°.
  Камерные смещения измеряются в блоках в ортонормированном кадре пути.
  У Anchor смещения применяются после обычных флагов наследования; включённое
  наследование масштаба добавляет длины осей мировой матрицы источника.
  Отражение источника уже учтено геометрией и направлением пути.
- Пустая/отсутствующая цель и циклическая ссылка не дают матрицу пути.
  Камера оставляет результат нижних клипов, Anchor использует штатный fallback.
  Одна точка или полностью схлопнутая кривая дают неподвижный конечный кадр;
  необратимая матрица не используется для «сохранить вид».
- `points` хранит порядок устойчивых ID, `curve` — единственный составной набор
  координат. `SplineSource`, `SplinePositions`, `SplineCurve`, `SplineMath`,
  `SplineOverlay` и `UISplinePointsEditor` используются совместно с IK.
  Свойства старых IK/Anchor/Tracker сохраняют прежние значения по умолчанию.

## Проверки

После закрытия клиента проекта:

```powershell
.\gradlew splineIKSolverTest splineIKRuntimeTest anchorInterpolationTest splineFormTest apiCheck
.\gradlew splineFormTest -PsplineUiChecks
```

Второй запуск требует рабочего desktop/GLFW: он создаёт невидимое окно без
графического контекста для состояния клавиш. Проверяются реальные виджеты,
автоключ, мультивыбор, структурные уведомления и ширины 120/180/300 с длинным
списком. Метрики шрифта тестовые; это не визуальная проверка интерфейса в игре.

Основной Fabric prelaunch-стенд проверяет binary save/load, копии, устойчивые ID,
Undo/Redo, film/state tracks, добавленные после ключей точки, мировую длину,
замкнутый шов, перемотку, независимые привязки, keep-view, камеры и их обратный
расчёт, маски/FOV, отдельный look-at, вложенность, отсутствующие цели и циклы.

При реализации Java и стенды запускались изолированно, не меняя `build/classes`
работающей игры. Визуальный игровой прогон новой сборки остаётся отдельной
проверкой: панель, гизмо в трёх редакторах, пипетка, длинные имена и итоговый кадр.
