# Составные анимируемые свойства

У модельной формы есть обычные свойства `ik`, `physics`, `wind`, `spline_ik`.
Каждое занимает одну дорожку; цепочка и точка выбираются внутри редактора ключа.
Все элементы составного ключа имеют общее время и интерполяцию, как кости в `pose`.
Отдельные костные дорожки по-прежнему добавляются поверх общей позы.

## Хранение и вычисление

- `bones` и `splines` описывают риг: кости, границы цепочки, порядок и ID точек,
  режимы вычисления. Структура не копируется в каждый ключ.
- `ik`, `physics`, `spline_ik` содержат анимируемые числа и привязки; `wind` — ветер.
  Исходное значение принадлежит свойству формы. Воспроизведение задаёт временное
  значение, которое снимается при сбросе анимации, в том числе после удаления канала.
- Старые публичные поля `FormBone.ik/physics`, параметры `SplineIK` и позиции
  `SplinePoint` остаются представлениями составного хранилища. Они не содержат
  второй исходный экземпляр. Уведомления об их редактировании идут через владельца
  составного свойства, поэтому Undo и автоключи записывают правильное значение.
- Сохранённая форма содержит анимируемые данные только в составных свойствах.
  Отдельные снимки/пресеты рига включают значения его представлений: это необходимо
  для полного восстановления структуры и координат через Undo/обмен.

IK идентифицирует цепочку по конечной кости, физика — по корневой. Spline IK
использует существующие постоянные ID цепочек и точек. Порядок точек хранится в риге.
Переименование подписи или перестановка точки не меняют её адрес.

Пропущенная цепочка в ключе берёт исходное состояние формы. Пропущенная spline-точка
берёт исходную позицию. Это разрешается **до интерполяции**, включая соседние ключи
для Auto; исходные ключи не меняются. Явно записанное значение по умолчанию
отличается от отсутствующего элемента. Новые элементы поэтому не движутся к нулю
в старых ключах. Данные удалённых элементов сохраняются в ключах, но не участвуют
в вычислении без соответствующей структуры; восстановление ID через Undo возвращает связь.

## Привязки и контекст

В IK ключ содержит Anchor-привязки `target` и `pole`, в физике — `target`.
Выбор актёра/прикрепления, смещение и флаги наследования используют стандартный UI.
Эти поля доступны только в редакторе каналов фильма. В настройках формы и ключах
анимационных состояний Anchor Binding не показывается; выбор костей самого рига
остаётся в настройках формы.

Связь вычисляется как мировая позиция и отдельный вес. Подключение/отключение
меняет вес, а не тянет позицию к началу координат. Смешивание состояний учитывает
уже вычисленный вес перехода между Anchor-ключами.

Новые составные свойства работают в фильме и состояниях. Состояние без
`AnchorResolver` применяет числа и локальные точки, но не создаёт внешние мировые
цели. Фильм разрешает привязки в проходе, который очищает solver overrides.
Ограничение старых специальных control-треков состояниями не переносится на новые свойства.

## Совместимость

Старые формы импортируют числа из костей и spline-точек в канонические свойства.
Если присутствуют оба формата, канонический payload имеет приоритет независимо
от порядка полей в файле. Неизвестные namespaced-поля составных контейнеров и
элементов сохраняются при чтении, копировании и записи. Неизвестные виды дорожек
и фабрики сохраняются существующим механизмом `foreignTracks`.

Существующие `IK_CONTROLS`, `PHYSICS_CONTROLS`, `WIND_CONTROLS` читаются через
`tracks.compatibility`. Новые дорожки этих видов каталог не предлагает.
Их историческая применимость и правила пропущенных элементов сохранены.

Старые независимые spline-каналы и target-каналы остаются самостоятельными кривыми
с исходными временами, интерполяцией и настройками сегментов. Они не запекаются и
не объединяются по набору времён. Существующие каналы доступны для редактирования.
В смешанных файлах старые общие controls применяются до новых свойств, отдельные
старые spline-поля — после них, костные наложения — после общей позы. Разрешённые
старые target-цели имеют приоритет над привязками составного свойства.
Видимое составное spline-значение включает старые кривые, в том числе при создании ключа.
Их наложение собирается при применении дорожек; обычное чтение свойства
и работа solver не обходят старые поля.

## Расширение и UI

`BaseKeyframeFactoryValue.animatable(boolean)` явно задаёт возможность анимации
независимо от видимости поля. По умолчанию свойство с фабрикой анимируемо;
статические параметры формы явно отключают эту возможность. Bound views
самостоятельных новых дорожек не объявляют. Фабрика свойства отвечает за формат,
копирование, интерполяцию, дополнение пропущенных элементов и смешивание.

`TrackCatalog` перечисляет общие свойства без создания каналов и без разворачивания
их внутренних полей. `buildSheets(..., properties)` создаёт каналы для редактируемых
строк. Категории/подписи/цвета остаются UI-метаданными; сборщик строк не разбирает
префиксы spline-адресов. Поля IK/physics/spline переиспользуются между формой и ключом
с разными callbacks записи.
